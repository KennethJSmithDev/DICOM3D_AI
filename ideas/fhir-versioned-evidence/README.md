# Synthetic FHIR source reader — local research

This optional experimental Node.js prototype inspects explicitly configured synthetic loopback sources for FHIR R4 (4.0.1), R4B (4.3.0), or R5 (5.0.0). It checks the source's CapabilityStatement and advertised read interaction before reading an allowed resource, checks resource type and ID, and returns the original parsed resource and SHA-256 of the retrieved bytes with the configured source ID and source-profile fingerprint.

It accepts `ImagingStudy`, `Observation`, and `DiagnosticReport`, plus `ImagingSelection` for R5 only. R4/R4B `Basic` cross-version selections are deliberately refused pending profile-aware qualification. It rejects version mismatch, unsupported resources, redirects, non-loopback addresses, missing advertised read, unexpected resource identities, malformed JSON and responses larger than 1 MiB. Fetches have a five-second timeout. Run `node --test ideas/fhir-versioned-evidence/reader.test.mjs` from the repository root.

The synthetic classification and source ID are caller assertions; they do not prove that data is synthetic or authorize access. Loopback does not authenticate the listener. Do not point this prototype at patient data, other applications, or an untrusted source. The basic reader is not a full FHIR profile validator, general version converter, or clinical authorization. The separately packaged experimental native classes do not replace the existing native AI Hub agent or modify the public Safe Demo.

## Reusing ISAIAH's scoped reader

`isaiah-scoped-interop.mjs` is an unchanged, same-owner copy of ISAIAH's independently qualified scoped interoperability reader. It uses configured loopback target and record IDs, a separate credential file, exact FHIR resource version and response-byte hashes, and does not expose credentials in the returned receipt. Its configured target name is not an authenticated server identity; loopback HTTP alone is not a secure production transport. The file also contains ISAIAH's existing DICOMweb reader; that path is not integrated or qualified here. It retains ISAIAH's Apache-2.0 license.

`node --test ideas/fhir-versioned-evidence/scoped-interop.test.mjs` exercises R4, R4B and R5 against local synthetic HTTP fixtures, including wrong-version, wrong-identity, wrong-hash, redirect and scope refusals. ISAIAH's separately retained qualification used a real local FHIR Candle server. Neither result establishes that this copy is installed, integrated with the DICOM3D_AI native agent, or qualified for R4/R4B imaging selection. Synthetic credentials belong only in private temporary files.

## Version-specific imaging inspection under development

`inspectPinnedSynthetic` adds a separate synthetic-only read path with an explicitly pinned resource version and SHA-256, and returns the original response bytes. It can retrieve a `Basic` resource from an R4 or R4B fixture, without asserting that the resource is an ImagingSelection. The older `inspectSynthetic` contract continues to refuse that type. The pin identifies expected content, not the network listener; the local HTTP path is unauthenticated and is not suitable for private data.

`selection-profile.mjs` inspects selected fields in R5 ImagingSelection and the declared [R4B cross-version Basic profile](https://hl7.org/fhir/uv/xver-r5.r4b/0.1.0/StructureDefinition-profile-ImagingSelection.html). The R4B profile is trial-use. For the separate [R4 cross-version profile](https://hl7.org/fhir/uv/xver-r5.r4/0.0.1-snapshot-2/StructureDefinition-R5-ImagingSelection-for-R4.html), an informative snapshot, it reads selected fields from the [nested cross-version extension](https://hl7.org/fhir/uv/xver-r5.r4/0.0.1-snapshot-2/StructureDefinition-ext-R5-ImagingSelection.html). These checks are not a full profile validator or a general version conversion.

`evidence-review.mjs` examines the preserved bytes, source identity, subjects, study and frame identities, and exact evidence references. Its `instance-binding.mjs` check also requires a separately supplied, pinned source binding and compares the complete CT instance set, selected CT context, CT/SEG series, SEG SOP and class, and segment subset. Missing, changed or inconsistent bindings fail closed. Matching a caller-supplied binding hash proves byte consistency; it does not authenticate the binding or authorize a selection. Even consistent records return `REVIEW_REQUIRED`: no automatic selection, citation acceptance or clinical conclusion is authorized.

The H000 tests compare the retained source binding and R5 fixture, with explicitly derived R4/R4B research projections for the fields being inspected. These derived representations are not original R4/R4B server records, and their declared profiles are not independently certified. Full profile validation and authenticated server identity remain open. This Node inspector is copied into the IPM package as an optional offline tool; it is not wired into the historical native AI Hub validator. A separate experimental native operation is described below. Run `node --test ideas/fhir-versioned-evidence/*.test.mjs` from the repository root.

The separate `native/` experiment does not consume the Node inspector above. Its R4/R4B and R5 field checks were exercised against a controlled local H000 research fixture in an owned Build 154 namespace. The experimental native R5 operation has a separate source-binding and exact-citation gate; R4/R4B remain review-only. The fixture is not a general FHIR integration or full profile validator, and HTTP Basic alone does not establish server identity. Existing historical native R5 source remains unchanged.

A separate `native/AuthFixture*` experiment adds a per-run synthetic reader credential, preapproved SHA-256 response pins and an IRIS-owned review validator. It remains fixed to a network-disabled local fixture; HTTP Basic authenticates the client and does not authenticate the server. An earlier native-agent test called the synthetic R4B evidence tool but returned Markdown-fenced JSON which the validator correctly rejected. `response_format_versioned.py` adds a narrowly gated provider output-format hint based on the exact permitted tool result; it does not modify the agent answer or the IRIS validator. The module installs the experimental native classes and fixture tools; the versioned response-format helper is separate local test infrastructure and is not installed by the module.

Subsequent isolated tests exercised the output-format hint with the actual native agent. A generalized R4B synthetic review and separate R4 and R5 synthetic reviews returned `Basic/seg-sel` or `ImagingSelection/seg-sel`, respectively. A separate headed witness used the experimental R5 H000 production, authenticated pinned research fixture, native agent, tool gate and deterministic validator to select the H000 lesion from an initially unselected state. A later separate witness used the installed experimental native classes and selected the lesion from an initially unselected state; its isolated model copy matched the expected SHA-256 before and after. The earlier transient model-read mismatch is still unexplained. These individual witnesses do not establish repeatability, clinical use, full FHIR profile validation, or the identity of a loopback server. R4/R4B H000 data used derived selected-field projections, not original server records. The private witness used a separately configured bridge and viewer; installing the package alone does not create that complete setup.

## Local fixture setup

The package copies `fixtures/evidence.json`, `fixtures/source-binding.json`, `fixtures/NOTICE.md`, `h000-projection.mjs`, `prepare-h000-fixture.mjs`, and `serve-h000-fixture.py` into its experimental FHIR resources. In an isolated Linux environment with Node.js and Python, generate a new fixture directory and mount it at `/run/dicom3d-ai-research` for IRIS:

```sh
node prepare-h000-fixture.mjs fixtures/evidence.json fixtures/source-binding.json /path/to/new-fixture
python3 serve-h000-fixture.py /run/dicom3d-ai-research
```

Run the server in the IRIS network namespace; it listens only at `127.0.0.1:18136`, creates an exclusive private per-run credential file and refuses a pre-existing private directory. Do not expose it externally or use patient data. An independently configured native provider relay at `127.0.0.1:53571` and the separate viewer are required for the optional R5 agent witness. The classes do not start those processes. The R4/R4B projections are research representations and remain review-only.
